Abstract

Spatial Training Room is an automated data factory that converts a 3D indoor reconstruction (Gaussian Splatting scene) + per-object AABB annotations + room polygon maps into Active Perception Learning (APL) training samples. Each sample is a 4D question: (init_view, expert_action_sequence, target_view, question, answer) . The initial viewpoint is deliberately selected so the question is unanswerable— the agent must actively navigate (pan, tilt, translate) to gather sufficient visual evidence before answering. Templates cover 19 spatial reasoning categories: occlusion, cross-room, counting, configuration, distance comparison, and more.

Key Highlights

📷

Active Perception by Design

Every init view is validated to be unanswerable under submit-time slot semantics. The agent must move to solve the task.

🏗

Real 3D Scenes

System Architecture

# Input scene/ 3D Gaussian Splatting reconstruction + AABB labels + room polygons templates/p0/*.yaml task "skeletons" — evidence slots, QA format, scoring ↓ task_generation/apl_tasks/template_active_generator.py Instantiate skeleton with scene objects Select init view # init must NOT satisfy slots (submit-time check) Expert search # BFS / greedy over camera actions Score trajectory # coverage × slot satisfaction ↓ out/fixed_v6/*.jsonl one line = one task with full expert trajectory ↓ testbench/render_real_tasks.py Render trajectory frames via Gaussian Splatting (CPU splat fallback) ↓ testbench/build_review_html.py self-contained local review HTML

Key Fix: tier2_override Init-View Selection

🔧 task_generation/apl_tasks/template_active_generator.py — Strict submit-time init check

Slots with tier2_override (e.g., target must be fully invisible at init) previously used the raw predicate fraction for the init-view rejection test. This allowed some tier2 slots to pass the init check even when the submit-time slot_satisfied(..., submit_only=True) would have rejected them.


Fix: the init-view loop now branches on s.tier2_override: tier2 slots call slot_satisfied() with submit_only=True; regular slots compare frac ≥ threshold as before. The init view is only rejected when enough slots are satisfied under this stricter criterion—ensuring tasks remain unanswerable at the starting viewpoint.


Result: init answerability drops to 0 / 25 = 0.0% on the probe regression.
